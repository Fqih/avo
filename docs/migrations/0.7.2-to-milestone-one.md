# Migration: 0.7.2 to Milestone One

Milestone One is backward-compatible for normal `avo` launches and existing
`~/.config/avo/auth.json` files.

## Credentials

The default credential backend remains the permission-protected JSON file. To
use the operating-system keyring for new credential writes:

```bash
python -m pip install 'avo[keyring]'
export AVO_CREDENTIAL_BACKEND=keyring
avo doctor
```

Use `AVO_CREDENTIAL_BACKEND=file` to force the legacy backend, or `auto` to
prefer the keyring and fall back to the file backend when unavailable. The
active backend is shown by `avo doctor`; secret values are never displayed.

## Model catalogs

`/model` now tries the provider's live catalog, then a short-lived cache, then
the maintained static fallback. Existing `/model NAME` and `AVO_MODEL` values
continue to work. Catalog files contain model metadata only and are stored
under `~/.config/avo/model-catalog` (override with `AVO_MODEL_CACHE_DIR`).

## Ollama Cloud

Local and Cloud operations are separate:

```bash
avo models ollama list
avo models ollama cloud list
avo models ollama cloud health
avo models ollama cloud usage
```

Cloud inspection requires an API/device key from the credential store or
`AVO_OLLAMA_API_KEY`. Cloud models are remote; `pull` remains a local
Ollama-only operation.

## Attachments

Chat accepts workspace paths pasted or dragged into the terminal, explicit
`@path` / `file://path` tokens, and `@clipboard` for a clipboard image. No
configuration change is required. Unsupported binary files, workspace
escapes, symlink escapes, and oversized payloads fail before inference.
