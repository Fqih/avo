# Migration: 0.7.x to Milestone Three

Milestone Three keeps existing provider and chat commands compatible while
making execution boundaries explicit. No credential values are copied into the
new project or user security configuration files.

## Configuration precedence

Security settings resolve in this order:

1. command-line overrides;
2. environment variables;
3. workspace `.avo/config.toml` or `.avo/config.json`;
4. user `~/.config/avo/config.toml` or `config.json`;
5. safe defaults.

Use `avo doctor` to see the resolved value and its source. Existing
`~/.avo/config.json` provider settings remain supported by the setup loader;
the new security resolver is intentionally separate from provider credentials.

## Execution posture

Sandbox execution is required by default, networking is disabled by default,
and the execution timeout defaults to 120 seconds. To make a deliberate local
development exception, scope it to the current process or workspace:

```bash
AVO_SANDBOX_REQUIRED=0 avo
```

Do not use `AVO_PERMISSION_MODE=bypass` for unattended runs. Child agents
cannot gain capabilities their parent does not have, and read-only delegation
is the default for discovery work.

## Plugins and web UI

Plugin installation requires an explicit `CONFIRM install NAME` action.
Editable installs and activation are disabled by default. Review a plugin
before enabling either setting and keep the plugin source pinned or local.

The local web dashboard keeps bearer/session authentication, same-origin
checks, CSRF protection, and exact mutation confirmation. Wildcard CORS is
rejected. These controls protect the dashboard; they are not a replacement
for network isolation or encrypted credential storage.

## Credentials and rollback

OAuth/API-key login is separate from permission protection. `avo login` stores
credentials through the selected credential backend; `AVO_PERMISSION_MODE`
controls tool actions and does not encrypt files. Check the backend with
`avo doctor` before changing it. To roll back a security setting, remove the
new `AVO_SANDBOX_*`, `AVO_PLUGIN_*`, or `AVO_WEB_*` variables and delete only
the corresponding project/user config keys; provider credentials and run
history are unaffected.
